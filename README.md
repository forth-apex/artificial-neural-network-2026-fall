## 作业格式：先看这一段

**每次作业只提交一个不超过 20 MB 的 ZIP 压缩包，内容仅限自己的程序源代码、必要的小型配置文件和环境配置说明，文件名为 `学号_姓名全拼.zip`。不提交大文件，也不使用网盘链接替代提交。** 姓名使用中文姓名的汉语拼音，按姓在前、名在后连写，建议全部小写；姓和名之间不加空格、下划线或其他分隔符。整个文件名只在学号与姓名全拼之间加一个英文下划线 `_`。

例如：张三，示例学号 2026000001 → **`2026000001_zhangsan.zip`**。这个学号只是示例，请换成自己的真实学号。请勿写成 `2026000001_zhang_san.zip` 或使用英文名代替中文姓名拼音。不同次作业仍使用同一命名格式，在提交单中填写各自的作业编号；不要在压缩包名后自行添加作业编号或版本号。

压缩包根目录必须包含以下两个文件夹，里面分别放对应程序：

```text
2026000001_zhangsan.zip
├── SANDBOX/
│   ├── README.md       # 必须：沙箱程序的环境配置与运行说明
│   └── 自己的沙箱程序源代码、必要的小型配置及依赖清单
└── BIGMODEL/
    ├── README.md       # 必须：大模型程序的环境配置与运行说明
    └── 自己的大模型程序源代码、必要的小型配置及依赖清单
```

- **`SANDBOX`**：放沙箱程序。
- **`BIGMODEL`**：放大模型程序。文件夹名全部大写，不含空格。
- 两个文件夹都用大写英文命名，分别为 `SANDBOX` 和 `BIGMODEL`，不含空格。打开 ZIP 后应直接看到这两个文件夹，不要在外面再包一层同名目录。文件夹内部可以按程序需要组织子目录和文件。
- **`SANDBOX/README.md` 和 `BIGMODEL/README.md` 都必须提供**，分别说明各自程序的环境配置及运行方法，不能只在压缩包根目录放一份总说明。
- **只交程序，不交模型权重、数据集、完整运行环境、输出结果、图片、视频或其他大文件；不提供大文件网盘链接代替上传。** 模型或数据的外部准备方法仅在对应 README 中说明。
- **公开提醒：本仓库和 Issues 附件公开可见，文件名中的学号与姓名拼音也会公开。** 除课程规定的学号、姓名拼音外，不要附带手机号、证件信息、密码、API 密钥或其他无关个人资料。

## 第三步：只整理程序，避免压缩出大文件

**请新建一个干净的“提交目录”，把要交的代码复制进去。不要直接压缩整个开发项目、整个工作区或整个运行环境。不要删除原项目里仍有用途的文件，只需让它们不进入提交副本。**

### 1. 建立两个文件夹并只复制必要文件

在提交目录中建立 `SANDBOX` 和 `BIGMODEL`，分别放沙箱程序和大模型程序。仅复制：自己编写的源代码、小型配置文件、依赖清单，以及下文规定的两份 `README.md`。程序内部有必要的小型子目录时可保留结构。不要把完整开发目录一次性复制进去再盲目压缩。

### 2. 以下内容不要放进提交目录

- **模型权重和检查点**：例如 `.pt`、`.pth`、`.ckpt`、`.safetensors`、`.onnx`、模型 `.bin`、微调检查点和下载后的模型目录。只交调用或加载模型的代码。
- **数据集与结果**：训练／测试数据、数据库、大型 CSV／JSON、模型输出、日志、训练曲线、图片、音频、视频、报告附件及中间文件。
- **虚拟环境和第三方依赖实体**：`.venv`、`venv`、`env`、Conda 环境目录、`site-packages`、`node_modules`，以及安装包、驱动、CUDA 安装包。用小型依赖清单描述依赖，不复制安装好的环境。
- **缓存和历史**：`__pycache__`、`.pyc`、`.cache`、Hugging Face／Torch 等模型缓存、`.ipynb_checkpoints`、`.git`，以及无关的编辑器缓存和临时文件。
- **编译和发布产物**：`build`、`dist`、可执行文件、打包后的应用、压缩包套压缩包等。交对应源代码和构建说明。
- **私密配置**：含真实 API 密钥、令牌或密码的 `.env` 等文件。必要时提供不含真实凭据的示例配置，真实值由运行者在自己电脑上填写。

这些是常见例子，不能只靠检查后缀：例如模型文件可能没有扩展名，日志和数据也可能叫 `.txt`。请按文件用途判断。

### 3. 怎样在开发时就避免把大文件带入作业

- 把模型权重、数据集、缓存、日志和输出文件保存在**提交目录之外**。代码通过可配置的路径引用它们，在 README 中写清楚如何准备；不要把这些目录复制到作业 ZIP。
- 调用大模型 API 时只提交调用代码、依赖清单和配置说明，不打包模型、接口返回的大批量结果或真实密钥。
- 使用本地模型时只提交加载／推理代码；在 README 中注明模型名称、版本或官方来源，以及运行前放置位置。不提交权重本体，也不提供网盘权重包代替作业。
- Python 依赖可用 `requirements.txt` 或 `pyproject.toml` 等清单说明；其他语言也提交对应的小型依赖清单。Conda 用户提交环境说明或小型 `environment.yml`，**不要打包整个 Conda 环境**。清单应对应本程序真正使用的依赖，避免混入其他项目环境或本机私有路径。
- 使用 Notebook 时，先在编辑器中执行 **Clear All Outputs／清除所有输出** 并保存，保留代码与必要文字说明，清掉嵌入的图片、大数组及训练输出；不需要为提交重新运行生成大批量输出。
- `.gitignore` 只管理 Git 的忽略规则，**不会自动从手动 ZIP 压缩包排除文件**。即使写了忽略规则，也要实际检查提交副本和 ZIP。

### 4. 两个文件夹分别写自己的环境配置 README.md（必须）

请创建两个独立文件：`SANDBOX/README.md` 与 `BIGMODEL/README.md`。README.md 是纯文本说明文件，可在代码编辑器中新建，确认真实后缀为 `.md`，不是 `README.md.txt`。两份说明分别对应各自程序；即使用同一套环境，也需在两处写清楚对应入口与运行步骤。

每份 README 至少包括以下内容，可按此结构填写，**把提示文字替换为自己程序的实际信息**：

```text
# 程序名称及用途
说明本文件夹实现什么功能。

## 运行环境
操作系统：实际使用的系统及版本。
语言／解释器／运行时：实际使用的名称及版本。
硬件要求：CPU 或 GPU；如依赖 CUDA 等，注明实际需要的版本。

## 依赖安装
列出实际使用的主要依赖和版本，说明依赖清单的文件名。
按顺序写出创建环境、安装依赖的步骤或命令。不要上传环境本体。

## 配置方法
说明需要修改的配置项、环境变量及填写位置。
需要 API 密钥时只写变量名和配置方法，不写真实密钥。
如果运行需要外部模型或数据，说明名称、官方来源、准备方法和外部路径；
这些大文件不在作业压缩包内，也不以大文件网盘包代交。

## 运行步骤
写清入口文件、工作目录、启动命令、参数及操作顺序。
说明预期出现什么现象或输出；不需要附带实际生成的大文件。

## 已知限制（如有）
说明联网要求、外部服务、资源限制或其他需要提前知道的事项。
```

### 5. 压缩前检查体积，再生成 ZIP

1. 在文件管理器中按“大小”排序，查看异常大的文件；右键查看 `SANDBOX` 和 `BIGMODEL` 的属性／简介，核对体积。如果目录很大，先检查是否误带了权重、数据、环境、缓存或输出。
2. 确认两份 `README.md` 已写好，代码、必要配置和小型依赖清单齐全。目标是提交最小、清楚的程序包，不是备份电脑上的完整项目。
3. **同时选中 `SANDBOX` 和 `BIGMODEL` 两个文件夹**，使用系统或压缩软件的“压缩为 ZIP”功能。Windows 可能显示“压缩为 ZIP 文件”或“发送到 → 压缩(zipped)文件夹”；Mac 可右键“压缩”。选择真正的 ZIP 格式，不能只把 RAR／7z 的后缀改成 ZIP。
4. 重命名为 `学号_姓名全拼.zip`，例如 `2026000001_zhangsan.zip`。检查不要出现 `.zip.zip`。电脑隐藏扩展名时，可在文件管理器显示扩展名后再核对。
5. 双击 ZIP，根目录应直接出现 `SANDBOX` 与 `BIGMODEL`。各自打开检查，必须有对应程序以及 `README.md`，不能是空文件夹，也不能在最外层多套一个项目目录。
6. **最终 ZIP 不得超过 20 MB**。这是本课程提交要求，表单不会自动执行该上限。如果超出，请回到提交副本排查并移除不应提交的文件，再重新压缩；不要拆成分卷压缩包、改用视频、上传环境包，或用网盘链接绕过要求。
7. 如果确认只剩必要源代码、小型配置和说明仍超出 20 MB，请先联系课程管理员说明情况，取得具体处理要求后再提交。不要自行改成大文件提交。

## 常见问题

**Code 页没有 Upload files，或者没有我的作业，怎么办？**
本课程用 Issues 提交附件，不需要 Code 页的写入权限。只要 Issue 已发布、附件可以下载，就是已经提交材料。

**看不到作业表单？**
登录后点击本页的 **立即提交作业**，再选择 **作业提交 / Homework submission**。如果已进入空白 Issue 页面，点 **Choose a different template** 返回模板选择页。

**上传失败或提示类型不支持？**
确认是真正的 ZIP、大小不超过 20 MB 且网络正常。RAR／7z 需重新压缩为 ZIP，不能只改后缀。ZIP 过大时，按第三步清理提交副本中的权重、数据、依赖实体、缓存和输出；不接受大文件或网盘链接代交。

**按钮点不了？**
检查标题、星号必填项和确认勾选。表单仅检查必填文字或勾选，不会自动检查 ZIP 命名、内部目录、附件内容或截止时间；这些需要本人核对。

**上传后文件链接有了，但 Issues 列表找不到？**
上传附件不等于发布提交单。还需要点页面底部 Create，出现独立 Issue 编号。如果网络中断，恢复后先按作者搜索，确认是否已发布，再决定是否重试。

**ZIP 不能在线预览？**
可以点击附件下载，再在电脑上解压检查；不能预览不代表提交失败。

**发现误传密码或其他不该公开的信息？**
及时联系管理员。如果泄露了 API 密钥或密码，还需自行更换或撤销。删除正文链接并不能保证已公开或被下载的文件被收回。

## 作业何时出现在主分支

当前流程：**同学在 Issues 提交 → 附件及时间记录保存在对应 Issue → 管理员在需要时另行整理到 main 分支。** 目前不自动整理，等管理员明确发起汇总时再做。

Issue 是提交记录，不是 Pull Request，不能直接点击“Merge issue”把附件放进主分支。之后整理需要下载、核对各人的最终版本，再将文件提交到 main，并保留原 Issue 编号或链接用于追溯。汇总范围和目录届时由管理员确定。

**主分支暂时没有作业文件不影响 Issues 提交成立。** 仓库 Code 页 **Download ZIP** 只包含主分支文件，不包含尚未整理的 Issues 附件。
