**本课程通过 Issues 收作业：无需邀请、无需 Fork、无需安装 Git，也不需要管理员审核或合并。每位同学需要自己的 GitHub 账号。**

## 先认识这几个按钮

- **Repository（仓库）**：本课程在 GitHub 上的主页。
- **README**：你正在看的使用说明，向下滚动即可阅读。
- **Issues**：本课程的作业提交区，可理解为一张张带附件的提交单，不是让你报告程序错误。
- **New issue**：新建提交单；**Create / Submit new issue**：发布提交单。
- **Code / main**：主分支文件区，当前主要放说明与表单配置；同学不用在这里找上传按钮。
- **Fork / Pull request**：本次交作业用不到，可忽略。

## 第一步：注册自己的 GitHub 账号（只做一次）

已有 GitHub 账号的同学直接跳到第二步。推荐在电脑上的 Edge、Chrome 等浏览器操作，不需要安装 Git、GitHub Desktop、插件，也不需要付费。界面文字可能更新，按钮以页面实际显示为准。

1. 打开 [GitHub 注册页面](https://github.com/signup)。如果从首页进入，点击右上角 **Sign up**（注册），不要点成 Sign in（登录）。
2. 按页面提示填写 **Email**（邮箱）：使用能正常接收邮件、自己能长期使用的邮箱。无需在课程群公开邮箱。
3. 填写 **Password**（密码）：设置一个符合页面要求、且与其他网站不同的密码，妥善保存。不要把密码发给管理员或同学。
4. 填写 **Username**（用户名）：这是以后登录和显示在提交记录里的账号名，可以用英文、数字及页面允许的符号。若提示已被使用，换一个名字。不要照抄管理员 forth-apex，每个人使用自己的账号。
5. 如果页面要求 Country/Region（国家或地区）等信息，按自己的真实情况填写。是否接收产品邮件可自行选择，不影响交作业。若显示 Google／Apple 等其他注册方式，也可以按页面提示使用；本文主要按邮箱注册说明。
6. 按页面提示完成 **Verify / 验证**。遇到人机验证请自己操作；访问受限时，尝试稍后重试、正常浏览器或其他可用网络。不要购买所谓代验证服务或提供密码。
7. 阅读 GitHub 的服务条款后，由本人完成 **Create account / Continue** 等注册确认步骤。
8. 登录刚填写的邮箱，找到 GitHub 的验证邮件，按页面提示输入验证码或点击验证链接。验证码有有效期，不要发到课程群；收不到先看垃圾邮件和邮箱拼写，再使用页面的重发功能。
9. 若出现套餐或用途问卷，选择免费方案 **Free** 即可；本课程交作业无需购买 Pro、Team，也无需填写信用卡。如果页面询问用途或经验，按实际情况选择。
10. 注册、邮箱验证完成后，记住自己的 GitHub 用户名。若另有安全验证或双重验证设置，请按 GitHub 提示自行完成，并妥善保存恢复方式。

## 第二步：登录并打开本课程

1. 打开 [课程仓库首页](https://github.com/forth-apex/artificial-neural-network-2026-fall)。页面显示 **Public**，所以未登录也能阅读说明，但交作业需要登录。

3. 登录成功通常会看到右上角的个人头像。打开头像菜单，可核对当前登录的是自己的账号。电脑上不同浏览器、不同浏览器用户资料和应用侧边栏的登录状态可能不互通。
4. 回到本页，点击顶部 **立即提交作业**。或者点击仓库顶部 **Issues → New issue → 作业提交 / Homework submission**（如果出现 Get started 按钮，点击它）。

## 第三步：整理作业文件

- 报告优先使用 PDF；代码可交 .py、.ipynb，多文件项目请打包为 ZIP，保留必要的目录结构和运行说明。
- 建议命名：ANN_HW01_你的课程代号或GitHub用户名_v1.pdf（或 .zip）。HW01 仅为格式示例，请填写老师实际发布的作业编号。
- 上传代码前，清除 Notebook 中不必要的大段输出；不要包含 .venv、venv、node_modules、`__pycache__`、.git、数据集、模型权重、训练检查点等大文件。依赖用 requirements.txt 或其他依赖清单说明。
- 本课程建议：每次作业附件合计不超过 20 MB，单个 PDF／ZIP／代码文件不超过 20 MB；图片每张不超过 8 MB；视频和大数据使用可访问的网盘链接。以上是课程提交约定，不是系统自动校验。
- GitHub Issues 当前平台上限：普通附件每个 25 MB，图片和免费仓库的视频每个 10 MB。文件类型或限制变化时，以 GitHub 页面提示为准。
- 不支持的文件类型请打包为 ZIP。大文件链接应有足够有效期，并提供必要的访问说明；只共享作业所需内容。

## 第四步：填写提交单并上传附件

1. 登录 GitHub，点击“立即提交作业”。确认仓库为 forth-apex/artificial-neural-network-2026-fall，页面出现作业编号、课程代号、版本号、附件等字段。带星号的字段必须填写。
2. 标题写为 [HW01] 课程代号或GitHub用户名，例如 [HW01] student-demo。不要公开完整学号、手机号或身份证信息。
3. 填写作业编号、课程代号或 GitHub 用户名、版本号和必要的运行说明。课程代号与本人身份的对应关系，按老师要求私下登记。
4. 将 PDF／ZIP 等文件拖入“作业附件或下载链接”的输入框，或点击输入框下方的附件按钮选择文件。请用电脑浏览器操作。
5. 等待上传完成：输入框里应出现文件链接，不能还停在 Uploading。多个文件可以依次上传到同一个提交单。网盘提交则粘贴下载链接、必要的访问说明和有效期。
6. 可点击输入框的 Preview（预览）检查附件链接；检查完成后勾选页面底部的确认项，点击 Create／Submit new issue（以页面实际按钮为准）。只上传附件、填写草稿或停在预览界面，还不算完成提交。
7. 发布后应跳转到独立的提交详情页，有标题、作者、发布时间及 #编号；地址末尾类似 /issues/12（12 只是示例）。这才表示提交单已发布。点击附件链接，确认文件正确、完整、可下载；ZIP 可下载后解压检查。用浏览器书签保存此页，或复制地址自行留存，作为提交凭据。
8. 不需要等待管理员批准或合并；发布成功表示材料已提交，是否符合截止时间和课程要求由老师判断。

## 常见问题

- 看不到 Code 页的 Upload files：正常，本课程走 Issues 附件提交，不需要仓库写入权限。
- 没有作业模板：确认打开的是本仓库的 Issues → New issue，刷新后重试。
- 发布按钮不可用：检查必填项、确认项和登录状态。表单只检查文字是否填写，不会自动验证附件已上传；请自行检查链接。
- 上传失败：检查网络、文件大小与类型；不支持的文件打包 ZIP，大文件改用网盘链接。网络恢复后先确认是否已经发布，避免重复提交。
- ZIP 无法在线预览：可以下载后解压检查，这不代表提交失败。
- 误传敏感内容：马上联系管理员；不要认为删掉正文链接就能撤回已经公开或被下载的文件。

## 公开范围与使用约定

这是公开仓库：Issue、评论、附件和下载链接可能被互联网任何人查看和下载。不要上传密码、API 密钥、个人资料、私有数据、成绩、受限制的教材或未经授权的内容。公开可见不代表允许抄袭或自由再分发，请遵守老师的课程要求和材料权利人的授权。由于无需邀请，其他 GitHub 用户也可能发 Issue，管理员可处理无关内容。

## 作业何时出现在主分支

当前流程是：同学在 Issues 提交 → 附件和提交时间留存在对应 Issue → 管理员在需要时另行汇总到 main 分支。**目前不自动汇总；由管理员另行发起整理。**

Issue 是提交记录，不是 Pull Request，所以不存在直接点击“Merge issue”把附件合并进主分支的操作。后续整理需要下载和核对附件，将最终版本作为文件提交到 main，并保留原 Issue 编号或链接用于追溯；外部网盘的大文件可能仍只保存链接。具体汇总范围与目录届时由管理员确定。

同学看到 Code 页没有自己的作业文件，不代表提交失败。只要 Issue 发布成功、附件链接能打开，就已完成材料提交；不要因为主分支暂时没有文件而重复提交。仓库首页 Download ZIP 只包含主分支文件，不包含尚未整理的 Issues 附件。
