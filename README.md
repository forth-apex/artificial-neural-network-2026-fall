## 作业格式：先看这一段

**每次作业提交一个 ZIP 压缩包，文件名为 `学号_姓名全拼.zip`。** 姓名使用中文姓名的汉语拼音，按姓在前、名在后连写，建议全部小写；姓和名之间不加空格、下划线或其他分隔符。整个文件名只在学号与姓名全拼之间加一个英文下划线 `_`。

例如：张三，示例学号 2026000001 → **`2026000001_zhangsan.zip`**。这个学号只是示例，请换成自己的真实学号。请勿写成 `2026000001_zhang_san.zip` 或使用英文名代替中文姓名拼音。不同次作业仍使用同一命名格式，在提交单中填写各自的作业编号；不要在压缩包名后自行添加作业编号或版本号。

压缩包根目录必须包含以下两个文件夹，里面分别放对应程序：

```text
2026000001_zhangsan.zip
├── sandbox/
│   └── 沙箱程序的代码及运行所需说明、配置等
└── large model/
    └── 大模型程序的代码及运行所需说明、配置等
```

- **`sandbox`**：放沙箱程序。
- **`large model`**：放大模型程序；两个英文单词之间是一个普通空格。不要写成 `large_model`、`large-model`、`largemodel` 或中文文件夹名。
- 两个文件夹都用小写英文命名。打开 ZIP 后应直接看到这两个文件夹，不要在外面再包一层同名目录。文件夹内部可以按程序需要组织子目录和文件。
- 每个文件夹建议附一份运行说明，说明入口文件、运行环境、依赖及启动步骤。提交自己的程序代码；大模型权重、数据集等大文件用下载说明或链接提供。
- **公开提醒：本仓库和 Issues 附件公开可见，文件名中的学号与姓名拼音也会公开。** 除课程规定的学号、姓名拼音外，不要附带手机号、证件信息、密码、API 密钥或其他无关个人资料。

## 先认识几个页面名称

- **Repository（仓库）**：课程在 GitHub 上的主页。
- **README**：你正在看的说明，向下滚动即可阅读。
- **Issues**：本课程的作业提交区，每个 Issue 可以理解为一张带附件的作业提交单。

## 第一步：注册自己的 GitHub 账号（只做一次）

已有账号的同学直接跳到第二步。推荐使用电脑上的 Edge、Chrome 等浏览器，不需要安装 Git、GitHub Desktop 或任何插件。GitHub 的界面文字可能更新，以页面实际显示为准。

1. 打开 [GitHub 注册页面](https://github.com/signup)。如果从首页进入，点击 **Sign up**（注册）；**Sign in** 是登录，不是注册。
2. 按页面提示填写 **Email**（邮箱），使用自己能正常收邮件、能够长期使用的邮箱，不必在群里公开。
3. 填写 **Password**（密码），设置符合页面要求、且与其他网站不同的密码。自己妥善保存，不要发给管理员、同学或代注册人员。
4. 填写 **Username**（用户名），使用页面允许的英文、数字等字符。若提示名字已被使用，换一个。每人使用自己的账号，**不要照抄管理员账号 forth-apex**。GitHub 用户名与压缩包里的姓名拼音可以不同。
5. 如果页面要求国家或地区等信息，按自己的真实情况填写；是否接收产品邮件可自行选择。如果选择 Google／Apple 等其他注册方式，则按对应页面提示操作。
6. 自己完成 **Verify / 验证**。遇到人机验证按页面要求操作；访问受限时可稍后重试，或使用正常浏览器、其他可用网络。
7. 阅读 GitHub 服务条款后，由本人完成 **Create account / Continue** 等注册确认步骤。
8. 登录刚填写的邮箱，找到 GitHub 验证邮件。按网页提示输入验证码或点击验证链接。验证码不要发给别人；收不到时先检查垃圾邮件和邮箱拼写，再使用页面的重发功能。
9. 如果出现套餐选择，选择 **Free（免费版）** 即可。本课程交作业无需购买 Pro 或 Team，也无需填写信用卡。用途问卷按实际情况填写。
10. 注册及邮箱验证完成后，记住自己的用户名。如果 GitHub 另有登录安全验证，请按页面提示自行完成，妥善保存恢复方式。

## 第三步：在电脑上整理并压缩作业

1. 新建一个临时目录，在里面建立 `sandbox` 和 `large model` 两个文件夹，分别放沙箱程序和大模型程序。
2. 在各自文件夹内检查代码、必要配置及运行说明是否齐全。不要包含密码、API 密钥、私人数据或受限制的材料。
3. 移除虚拟环境、依赖安装目录、缓存、Git 仓库历史及大文件，例如 `.venv`、`venv`、`node_modules`、`__pycache__`、`.git`、模型权重、训练检查点和大数据集。用依赖清单和下载说明代替这些内容。Notebook 可清除不必要的大段输出。
4. **同时选中 `sandbox` 和 `large model` 这两个文件夹**，使用系统或压缩软件的“压缩为 ZIP”功能。Windows 版本不同，可能显示“压缩为 ZIP 文件”或“发送到 → 压缩(zipped)文件夹”；Mac 可右键选择“压缩”。选择 ZIP 格式，不要只把 RAR／7z 文件的后缀改成 ZIP。
5. 把生成的 ZIP 重命名为 `学号_姓名全拼.zip`，例如 `2026000001_zhangsan.zip`。注意不要出现 `.zip.zip`；若电脑隐藏扩展名，可先在文件管理器中显示扩展名再核对。
6. 双击 ZIP 检查，第一层应直接出现 `sandbox` 和 `large model`；分别打开确认程序文件实际存在。文件夹为空、程序放反或额外包了一层目录时，请修正后重新压缩。
7. 检查大小。本课程建议每次作业的 ZIP **不超过 20 MB**。这是提交约定，表单不会自动检查。大文件请提供可访问的网盘链接，并说明有效期；文件仍应按相同命名和目录要求整理。

GitHub Issues 当前普通附件每个上限为 25 MB；图片及免费仓库的视频每个上限为 10 MB。这与 Code 页上传文件的规则不同，限制变化时以页面提示为准。选择 20 MB 是为上传留出余量。不要把大模型权重或整个运行环境打包进去；确实需要大文件时，在附件栏交 ZIP 的下载链接，并确保老师能够访问。

## 第四步：填写提交单并上传 ZIP

1. 打开 [立即提交作业](https://github.com/forth-apex/artificial-neural-network-2026-fall/issues/new?template=homework.yml)，确认仓库是 `forth-apex/artificial-neural-network-2026-fall`。页面应显示作业编号、GitHub 用户名、版本号和附件等字段，星号表示必填。
2. **修改标题**为 `[作业编号] 学号_姓名全拼`，例如 `[HW01] 2026000001_zhangsan`。`HW01` 只是格式示例，请使用老师实际通知的编号，不要保留模板里的提示文字。
3. “作业编号”填老师给出的编号；“GitHub 用户名”填自己当前登录的账号；首次提交的版本号用 `v1`。
4. 把准备好的 ZIP **拖入“作业 ZIP 压缩包或下载链接”输入框内部**。也可点击该输入框下面的附件按钮（英文可能是 **Paste, drop, or click to add files**），在弹出的文件选择窗口里选择 ZIP 并打开。
5. 等待上传完成，输入框里应出现类似 `[2026000001_zhangsan.zip](https://github.com/user-attachments/files/...)` 的附件链接。不要删除它，也不要在仍显示 **Uploading** 时发布。若使用大文件网盘链接，则在同一输入框粘贴链接、必要的访问说明及有效期。
6. 可在“运行说明或补充说明”里概述两个程序的运行方式、环境和依赖；详细说明也可放在 ZIP 的各程序文件夹中。
7. 可点击 **Preview**（预览）检查链接，再勾选底部确认项。确认标题、文件名、目录结构和附件都正确后，点击 **Create / Submit new issue**（实际按钮文字以页面为准）。仅拖入文件、填写草稿或停在预览界面都还不算提交完成。
8. 发布成功后应跳到独立的详情页，有标题、作者、发布时间和 `#编号`，地址类似 `/issues/12`（12 仅为示例）。**保存这个网址作为提交凭据。**
9. 点击自己发布的 ZIP 附件链接，下载后打开检查，确认不是旧文件、空包或错误版本。网盘链接也要检查访问权限和有效期。
10. Issue 发布成功且附件可用，就表示材料已提交，不需要管理员批准或合并；是否按时、内容是否符合课程要求由老师判断。

## 第五步：修改、补交和版本说明

**同一位同学、同一次作业只保留一个 Issue。** 更正时打开原 Issue，在下方评论输入框中上传新版 ZIP，写明“v2，替代 v1，修改内容：……”并发布评论。新版 ZIP 仍叫 `学号_姓名全拼.zip`，版本号写在评论里，不改压缩包命名格式。

每次上传会生成新的附件链接；请不要删掉旧记录，方便老师按时间和版本判断最终材料。不要另开多个提交单，也不要覆盖或冒用他人提交。截止时间和补交规则以老师通知为准；更新附件不会把后来的上传变成截止前提交。

## 第六步：查找自己的提交

- 点击 **Issues**，在搜索框输入 `is:issue author:你的GitHub用户名`，例如把末尾换成自己的真实账号，可查看全部提交，包括已关闭的提交单。
- 按作业查找可搜索 `is:issue "HW01"`，按学号查找可搜索 `is:issue "你的学号"`。
- 如果默认只显示 Open，可用上述搜索包含 Closed。Open／Closed 只是提交单状态，不代表已评分、及格或按时；同学自己不需要关闭提交单。
- 保存提交详情页网址最方便。提交前可先搜索自己的账号，避免重复新建。

## 常见问题

**Code 页没有 Upload files，或者没有我的作业，怎么办？**
本课程用 Issues 提交附件，不需要 Code 页的写入权限。只要 Issue 已发布、附件可以下载，就是已经提交材料。

**看不到作业表单？**
确认登录后打开本页的“立即提交作业”，或按 Issues → New issue → 作业提交进入；若浏览器缓存旧页面，可刷新后重试。

**上传失败或提示类型不支持？**
确认是真正的 ZIP、大小合规且网络正常。不接受 RAR／7z 时重新压缩为 ZIP，不要只改后缀；过大的 ZIP 去掉权重、依赖和数据等，确有需要则交网盘下载链接。

**按钮点不了？**
检查标题、星号必填项和确认勾选。表单仅检查必填文字或勾选，不会自动检查 ZIP 命名、内部目录、附件内容或截止时间；这些需要本人核对。

**上传后文件链接有了，但 Issues 列表找不到？**
上传附件不等于发布提交单。还需要点页面底部 Create，出现独立 Issue 编号。如果网络中断，恢复后先按作者搜索，确认是否已发布，再决定是否重试。

**ZIP 不能在线预览？**
可以点击附件下载，再在电脑上解压检查；不能预览不代表提交失败。

**发现误传密码或其他不该公开的信息？**
及时联系管理员。如果泄露了 API 密钥或密码，还需自行更换或撤销。删除正文链接并不能保证已公开或被下载的文件被收回。

## 作业何时出现在主分支

当前流程：**同学在 Issues 提交 → 附件及时间记录保存在对应 Issue → 管理员在需要时另行整理到 main 分支。** 目前不自动整理，等管理员明确发起汇总时再做。

Issue 是提交记录，不是 Pull Request，不能直接点击“Merge issue”把附件放进主分支。之后整理需要下载、核对各人的最终版本，再将文件提交到 main，并保留原 Issue 编号或链接用于追溯；大文件可能仍保留为下载链接。汇总范围和目录届时由管理员确定。

**主分支暂时没有作业文件不影响 Issues 提交成立。** 仓库 Code 页 **Download ZIP** 只包含主分支文件，不包含尚未整理的 Issues 附件。
